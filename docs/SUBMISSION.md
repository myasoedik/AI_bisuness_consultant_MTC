# Порядок проверки и сдачи

Репозиторий: https://github.com/myasoedik/AI_bisuness_consultant_MTC

## Комплект

- `docs/presentation.pdf` — презентация со ссылкой на репозиторий и порядком проверки на первом слайде.
- `README.md` — запуск, переменные окружения, порты, зависимости и ограничения.
- `Dockerfile`, `compose.yaml`, `.dockerignore`, `.env.example`, `requirements.txt` — запуск приложения.
- `solution.py` и `energytool/` — общая логика чата и автоматического сабмита.
- `tests/` — самостоятельные проверки; исходные выгрузки не нужны для основных тестов.

Вариант финальной сдачи: загрузить PDF на платформу, указав репозиторий,
или загрузить `output/energytool-mvp.zip` с кодом, документацией и PDF внутри.
Просто ссылка на GitHub не заменяет предусмотренную кейсом загрузку.
Если репозиторий приватный, предоставьте доступ аккаунту `hack-and-change-2026`.

## Проверка демо за 5 минут

1. Скачать репозиторий или распаковать ZIP. Запустить Docker Desktop.
2. Скопировать `.env.example` в `.env`. Для вымышленного демо заполнить
   `LLM_BASE_URL=https://openrouter.ai/api/v1`, свой `LLM_API_KEY`,
   `LLM_MODEL=nvidia/nemotron-3.5-lightning:free`. Ключ не включать в сдачу.
3. Выполнить `docker compose -f compose.yaml -f compose.demo.yaml up --build -d`.
4. Открыть http://localhost:8000, спросить о расходах на трёх вымышленных складах,
   уточнить, что расходы выросли только на одном. Проверить источники и время ответа.
5. Сохранить заявку с выдуманными ФИО, телефоном и компанией.
   Открыть http://localhost:8000/manager и проверить резюме и связанную переписку.
6. Нажать «Новый диалог»: контекст пустой, старый диалог доступен в истории.
   Для просмотра более ранних сессий нажимать «Показать ещё».

Без ключа демонстрируется поиск, но это не полноценная консультация с LLM.
Демо показывает механизм на вымышленной базе; оно не подтверждает качество EnergyTool.

## Настоящая база и автоматическая оценка

1. Использовать исходную базу из выдачи организаторов, не из публичного репозитория.
   Для веб-режима путь указан в README. Для сабмита `DATA_DIR` содержит
   `questions.csv` и `knowledge-base.zip`.
2. При запуске на конкурсной платформе API Qwen и входные материалы предоставляет
   среда организаторов. Скрипт читает `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`
   (включая алиасы из образца сабмита). Покупать отдельный API или включать ключ
   OpenRouter в ZIP не требуется. Для самостоятельного повторения этого запуска
   нужны те же параметры среды.
3. Для веб-режима выполнить `docker compose up --build -d`.
   Пройти консультацию до заявки на материалах EnergyTool с тестовыми контактами.
4. Для проверки CSV выполнить `python solution.py` в условиях регламента,
   проверить `submission.csv` (`id,answer`, исходные ID, отсутствие ответов об ошибке API).
5. Создать `python scripts/package_submission.py`. Загрузить `output/submission.zip`
   на платформу и получить результат LLM-судьи больше нуля — условие допуска.
6. Загрузить финальный PDF или полный ZIP. Соблюсти сроки и ограничения регламента.

## Что уже проверено и что требует внешнего доступа

Проверены автоматические тесты, сборка Docker из официального Python-образа,
сохранение данных и демо с OpenRouter. Поиск на 18 открытых вопросах проверяется
локально; это не оценка качества ответов LLM.

Не подтверждены API организаторов, точные ресурсные лимиты и результат платформы.
Готовность комплекта не означает получение допуска. API-ключи, переписки,
контактные данные и исходные выгрузки отсутствуют в материалах сдачи.

Для хакатона не требуются живая связь с оператором, CRM или почта.
Прототип локальный: публичное размещение требует авторизации и изоляции посетителей.

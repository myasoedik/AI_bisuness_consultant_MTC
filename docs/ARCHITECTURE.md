# Устройство решения

Браузер обращается к локальному Python HTTP API. Консультант выполняет BM25-поиск
по фрагментам Markdown/TXT, объединяет результаты текущей реплики и истории
по рангам, затем передаёт контекст OpenAI-совместимой модели. SQLite хранит
историю, источники, время ответа, заявки и ключи повторных запросов.

Словарь бытовых формулировок связывает, например, «фото» с фотографией,
«симки» с SIM, а «расширить» с поэтапным вводом. Правила работают независимо
от ID тестов и не содержат готовых ответов. Векторного поиска нет.

На генерацию идут 8 фрагментов и вся история текущего диалога. Контекст не
обрезается скрыто. При превышении `MAX_CONTEXT_CHARS` (120 000 символов JSON)
модель не вызывается: клиент получает явное сообщение и может оставить заявку
или открыть новый диалог. Полная история остаётся в SQLite. Предел в символах
не заменяет токенный лимит API: его нужно сверить с регламентом организаторов.
История доступна страницами по 50 сессий, без ограничения общего числа.
При отсутствии результатов поиска возвращается отказ с предложением специалиста.
Предыдущие выдержки режима поиска и сообщения об ошибках не используются как
ответы ассистента при следующем обращении к модели.

Для повторов браузер посылает `request_id`. На сервере одинаковый ID с тем же
содержимым возвращает сохранённый результат, а с изменённым содержимым получает
409. Пара сообщений и результат сохраняются транзакционно. Это защищает от
повторной доставки после потери HTTP-ответа. Сбой процесса непосредственно во
время вызова модели может потребовать нового вызова после перезапуска.

Два режима:

- **Кейс:** исходная база через read-only mount, отдельный том `consultant-data`.
  OpenRouter блокируется для генерации по этой базе по умолчанию. Согласованное
  использование внешнего API можно явно разрешить `ALLOW_CASE_EXTERNAL_API=1`.
- **Демо:** вымышленная база «СкладЛаб», API OpenRouter, отдельный том `demo-data`.
  Переключение режима не удаляет ни один том.

API-ключ используется только сервером. Приложение не пишет сообщения и ключи
в HTTP-логи. Страницы выводят пользовательский текст через `textContent`.
POST из другого origin отклоняется, SQL использует параметры. Эти меры не
заменяют авторизацию: приложение слушает только локальный интерфейс хоста.

Режим сабмита использует то же ядро с отдельной историей каждого CSV-кейса.
Тестовый вход из чужого диалога не попадает в следующий. Ошибка модели создаёт
честный текст о недоступности сервиса. Это не гарантирует баллы на платформе.

План внедрения: заменить учебный HTTP-сервер промышленным, добавить владельца
к каждой сессии, вход менеджеров, политику хранения, ограничения запросов и
серверный адаптер передачи заявок в CRM. Для текущего задания внешняя отправка
заявки и соединение с живым оператором не реализованы и не требуются.

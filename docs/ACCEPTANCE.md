# Проверка MVP

Дата ревизии: 15 ноября 2026 года. Проект предназначен для локального показа
с тестовыми контактами. Авторизации и разграничения доступа в нём нет.

## Сценарий показа за 5 минут

1. Запустите `docker compose -f compose.yaml -f compose.demo.yaml up --build -d`.
2. Откройте http://localhost:8000. Вверху должно быть «Демо с AI».
3. Напишите: «У нас три склада, хотим сократить расходы на электричество».
4. Дождитесь ответа и уточните: «Расходы выросли на одном складе, режим работы не менялся».
5. Откройте источники и время ответа. В демо должны быть только фрагменты `demo.md`.
6. Оставьте заявку с выдуманными данными. Откройте её карточку менеджера.
7. Убедитесь, что контакты, резюме и сообщения относятся к текущему диалогу.
8. Создайте новый диалог. Старый остаётся доступен в истории, но не участвует в новой консультации.
9. Перезапустите контейнер. Заявка и история должны сохраниться.

## Автоматические проверки

`python -m unittest discover -s tests -v` проверяет:

- поиск по полным документам, контекст коротких и длинных диалогов;
- отказ от отправки базы кейса в OpenRouter по умолчанию;
- обработку недоступности и обрезанного ответа модели;
- сохранение сессий, сброс контекста и отказ записи в закрытую сессию;
- валидацию тестовых заявок и повтор запросов без дубликатов;
- поиск, пагинацию и карточку заявки менеджера;
- реальный запуск `solution.py` с ZIP, CSV и локальным имитатором API;
- сохранение исходных ID, формат ответов и изоляцию тест-кейсов.

`python scripts/evaluate_retrieval.py` выполняет локальную проверку поиска
по 18 примерам из материалов. Отчёт: `output/retrieval-evaluation.json`.
Метрика проверяет наличие вручную заданных признаков опорных сведений среди
8 фрагментов. Это открытый набор разработки, не независимая выборка и не
оценка качества ответов или LLM-судьи. До доработки словаря: 13/18, после: 18/18.

## Результат финального прогона

18 автоматических тестов прошли; синтаксис обоих JavaScript-файлов проверен Node.js.
Демо-контейнер запущен, Docker healthcheck показывает `healthy`. После пересоздания
контейнера сохранились 1 заявка и 8 диалогов. Проверено соответствие заявки её
переписке и совпадение шести файлов интерфейса с текущими исходниками.

На вымышленный вопрос о трёх складах модель ответила через приложение за 985 мс,
уточнив, выросли ли расходы на всех складах или на одном. Первый запрос завершился
ошибкой доступности; последующая проверка API и повторный запрос прошли успешно.
Это единичный замер, а не гарантия скорости или доступности бесплатной модели.

Свежая сборка из `python:3.13-slim` была прервана из-за DNS Docker Hub.
Для текущего запуска обновлённые исходники собраны поверх ранее установленного
образа проекта. Проверка полной сборки с загрузкой базового образа остаётся
зависимой от доступности Docker Hub. Обычная команда запуска в README сохранена.

## Что ещё не подтверждено

- Качество ответов на настоящую базу с Qwen организаторов и результат лидерборда.
- Лимиты и точные требования технического регламента, которого нет в папке.
- Визуальная автоматическая проверка браузером: инструмент недоступен.
  Пользователь проверял работающие чат, форму и экран менеджера вручную.
- Работа под высокой нагрузкой и защита публичного многопользовательского сервиса.

## Перед конкурсной отправкой

Получите API организаторов, заполните `.env`, выполните кейсовые вопросы,
сверьте ZIP с техническим регламентом и загрузите его на платформу.
Для допуска нужен ненулевой результат LLM-судьи. Эта проверка не заменяется
успешными локальными тестами. Не отправляйте рабочие ключи, базы диалогов и
контактные данные. Исходные выгрузки не публикуйте в открытых репозиториях.

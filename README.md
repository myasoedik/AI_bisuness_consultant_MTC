# EnergyTool — локальный MVP

Консультант по базе знаний, веб-чат, история всех сессий, тестовые заявки и экран
менеджера. Общее Python-ядро используется также в solution.py. Это локальный
прототип без авторизации; не открывайте его как публичный сервис.

## Быстрый запуск демо

Запустите Docker Desktop. Скопируйте `.env.example` в `.env` и внесите свой ключ.
Для OpenRouter: `LLM_BASE_URL=https://openrouter.ai/api/v1`, `LLM_API_KEY` — ваш
ключ, `LLM_MODEL=nvidia/nemotron-3.5-lightning:free` — проверенная бесплатная
модель. Доступность и лимиты зависят от провайдера.

```sh
docker compose -f compose.yaml -f compose.demo.yaml up --build -d
```

Чат: http://localhost:8000. Менеджер: http://localhost:8000/manager.
Демо использует вымышленную базу «СкладЛаб» и отдельный том `demo-data`.
Модель работает в облаке, мощный ноутбук не требуется. Вводите выдуманные
вопросы и контакты. Без ключа работает поиск с выдержками.

После изменения `.env` повторите команду `up`. Команда `restart` не применяет
новые переменные. После изменения кода используйте `--build` и обновите браузер.

```sh
docker compose -f compose.yaml -f compose.demo.yaml ps
docker compose -f compose.yaml -f compose.demo.yaml logs --tail=30
docker compose -f compose.yaml -f compose.demo.yaml stop
```

## Настоящая база кейса

Положите оригинальную базу в
`drive-download-20261114T123852Z-1-001/knowledge-base`. Выгрузка не входит в ZIP
проекта: используйте предоставленные организаторами материалы.
Настройте `.env` на API организаторов. Модель из кейса — Qwen3.8-27B, точный ID
сверяется с техническим регламентом. Самостоятельно модель разворачивать не нужно.

```sh
docker compose up --build -d
```

Кейсовый режим использует отдельный том `consultant-data`. Переключение режимов
не удаляет историю. Отправка базы кейса в OpenRouter по умолчанию отключена,
даже при наличии ключа. Только после согласования внешнего API можно установить
`ALLOW_CASE_EXTERNAL_API=1`. В демо исходных материалов нет.

## Без Docker

Нужен Python 3.13, сторонних runtime-зависимостей нет:

```sh
python -m energytool.server
```

По умолчанию используются настоящая база и `data/energytool.sqlite3`.
Для демо задайте `DEMO_MODE=1`, `KB_PATH=demo-knowledge-base`,
`DB_PATH=data/demo.sqlite3`, `LLM_REASONING_OFF=1`, `MAX_TOKENS=4096`.

## Основной сценарий

Задайте вопрос, уточните ситуацию, проверьте источники и время. Нажмите
«Оставить заявку» и заполните выдуманные ФИО, телефон и компанию. После сохранения
появятся номер, резюме и ссылка на карточку менеджера.

Менеджер видит контакты, резюме на момент заявки и полную переписку связанной
сессии. Есть поиск по компании, имени и телефону, страницы по 50 заявок,
автообновление списка раз в 15 секунд. Ручная кнопка «Обновить» загружает также
свежие сообщения карточки. Внешней отправки в CRM или реального звонка нет.

«Новый диалог» сбрасывает контекст. Все сессии, включая разговоры без заявки,
сохраняются и доступны для чтения. Старые сообщения не используются в новом
диалоге. После закрытия вкладки новый запуск начинает отдельную сессию.

Подробный сценарий: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Архитектура

- `energytool/core.py`: разбиение Markdown/TXT, BM25, словарь формулировок,
  объединение рангов текущего вопроса и истории, вызов LLM.
- `energytool/storage.py`: SQLite, транзакции, защита от дубликатов при повторной
  доставке запроса с тем же `request_id`.
- `energytool/server.py`: HTTP API локального прототипа и статические страницы.
- `web/`: адаптивный чат и экран менеджера без сборки и внешних CDN.
- `solution.py`: независимые CSV-кейсы с тем же ядром консультации.

Модель получает до 8 фрагментов, последние 20 реплик и ранние сообщения клиента
отдельным контекстом до 12 000 символов. Полная история хранится в SQLite.
Системная инструкция ограничивает ответ фактами базы, но не гарантирует
отсутствие галлюцинаций. [Подробнее об архитектуре](docs/ARCHITECTURE.md).

## Проверки

```sh
python -m unittest discover -s tests -v
python scripts/evaluate_retrieval.py
python scripts/check_api.py
python scripts/check_web.py
```

Первые две команды полностью локальные. `check_api.py` посылает выдуманный вопрос
на настроенный API. `check_web.py` проверяет работающий демо-чат и не запускается
в кейсовом режиме. Ключи не выводятся.

На ревизии 15.11.2026 прошли 18 тестов. В 18 открытых примерах поиск находит все
заданные признаки опорных сведений в top-8: 18/18 после доработки, 13/18 до неё.
Это покрытие поиска на наборе разработки, а не точность ответов модели.
Отчёт: `output/retrieval-evaluation.json`. Оценка LLM-судьи неизвестна.

## Сабмит и комплект

В `DATA_DIR` платформа передаёт `questions.csv` (`id,question`) и
`knowledge-base.zip`. Поддерживаются `train.csv`, `kb.zip`, `knowledge_base.zip`
и каталог `knowledge-base`. Диалоги разбираются по строкам `Пользователь:` и
`Ассистент:`; ответ формируется на последнюю реплику клиента.

```sh
python solution.py
python scripts/package_submission.py
python scripts/package_project.py
```

- `submission.csv`: колонки `id,answer`, исходные ID и одна физическая строка на ответ.
- `output/submission.zip`: точка входа, ядро и requirements. Без вопросов, базы и ключей.
- `output/energytool-mvp.zip`: код, тесты, документация, вымышленная база, PDF и SHA-256-манифест.
- `output/pdf/energytool-presentation.pdf`: презентация для локального показа и сдачи в ZIP.

Для повторной генерации PDF нужен PyMuPDF и Arial (Windows) или DejaVu Sans
(Linux): `python scripts/build_presentation.py`. Это зависимость сборки PDF,
а не приложения. Сначала создайте PDF, затем запустите `package_project.py`.

## Переменные окружения

| Имя | Назначение / значение по умолчанию |
|---|---|
| `LLM_BASE_URL` | Корень OpenAI-совместимого API, включая `/v1`, если требуется |
| `LLM_API_KEY` | Серверный секрет, только в `.env` или окружении |
| `LLM_MODEL` | `qwen/qwen3.8-27b`, переопределяется выбранным провайдером |
| `MAX_TOKENS` | 1200, демо Docker задаёт 4096 |
| `TEMPERATURE` | 0 |
| `MAX_WORKERS` | 3, от 1 до 8, для CSV-сабмита |
| `LLM_REASONING_OFF` | 1 отключает reasoning для поддерживающих это моделей OpenRouter |
| `DEMO_MODE` | 0, демо Docker задаёт 1 |
| `ALLOW_CASE_EXTERNAL_API` | 0, защита базы кейса от отправки в OpenRouter |
| `KB_PATH` | Папка базы или ZIP, в Docker `/knowledge-base` |
| `DB_PATH` | SQLite, по умолчанию `data/energytool.sqlite3` |
| `DATA_DIR` | `data`, входные файлы сабмита |
| `HOST`, `PORT` | `127.0.0.1`, 8000; внутри контейнера `0.0.0.0` |

Алиасы API: `BASE_URL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `GEN_MODEL`,
`OPENAI_MODEL`. Docker использует основные имена. Ключи, сообщения и контакты
не пишутся в HTTP-логи.

## Границы готовности

Прототип предназначен для локального показа: нет авторизации и изоляции разных
посетителей. Порт Docker привязан к `127.0.0.1`. Для внешнего внедрения нужны
роли, владелец каждой сессии, политика хранения и промышленный HTTP-сервер.

Качество ответов Qwen по настоящей базе ещё не проверено: нет ключа организаторов
и технического регламента. Визуальная автоматическая проверка браузером недоступна;
работа интерфейсов проверялась пользователем вручную. Векторный индекс и реранкер
не подключены. Боковая панель показывает последние 200 сессий, полная история
остаётся в SQLite. Аварийное закрытие вкладки может не доставить уведомление
завершения, но следующий запуск всегда создаёт новую сессию.

Не публикуйте исходные выгрузки, `.env`, SQLite и контактные данные в открытом
доступе. Конкурсную готовность подтверждают технический регламент и ненулевой
результат на платформе. Перечень проверок: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).
